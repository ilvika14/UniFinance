BUG #10: getUserTransactions spreads unvalidated query into Prisma           
                                                                                  
     File: actions/transaction.ts:283-300                                         
                                                                                  
     The function accepts a raw query object and spreads it directly into         
     Prisma's where clause without any validation. This could allow injection     
     of arbitrary filters.                                                        
                                                                                  
     The broken code:                                                             
                                                                                  
     export async function getUserTransactions(query = {}) {                      
       const user = await getOrCreateUser();                                      
       const transactions = await prismaDb.transaction.findMany({                 
         where: {                                                                 
           userId: user.id,                                                       
           ...query,  // ← unvalidated, could filter by anything                  
         },                                                                       
       });                                                                        
     }                                                                            
                                                                                  
     What could go wrong: A malicious caller could pass query = { userId:         
     "other-user-id" } and see another user's transactions (bypassing the         
     userId: user.id filter since the spread overwrites it).

      BUG #16: No loading.tsx files for server-rendered pages                    

     Files: Missing from app/(main)/dashboard/, app/(main)/account/[id]/, app/
     (main)/transactions/create/
  
     These pages are server components that fetch data on the server. Without 
     a loading.tsx, users see a blank screen while data loads. Next.js App      
     Router supports loading.tsx files that automatically show a loading      
     state while the page's async server component resolves.                    
  
     What's missing:
  
     app/(main)/dashboard/loading.tsx        ← should exist
     app/(main)/account/[id]/loading.tsx     ← should exist
     app/(main)/transactions/create/loading.tsx ← should exist
                                                                                
     What happens: Users click "Dashboard" or "Account" and see nothing — no    
     spinner, no skeleton, no feedback — until the server responds.             

     The fix: Add loading.tsx files with skeleton/spinner UI to these routes.
